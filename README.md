# Shell Emulator

Эмулятор языка оболочки ОС с консольным интерфейсом (CLI).
Практическая работа по дисциплине «Конфигурационное управление»,
вариант №3.

## Общее описание

Программа имитирует работу в командной строке UNIX-подобной ОС.
Приглашение к вводу формируется на основе реальных данных ОС,
например `username@hostname:~$`.

Реализовано (этап 1 — REPL):

- консольный интерфейс (CLI);
- приглашение вида `username@hostname:~$`;
- простой парсер: команда и аргументы разделяются по пробелам;
- сообщения об ошибках (неизвестная команда, неверные аргументы);
- команды-заглушки `ls`, `cd` и команда `exit`.

Этап 2 — конфигурация:

- параметры командной строки `--vfs`, `--prompt`, `--script`;
- отладочный вывод всех параметров при запуске;
- стартовый скрипт: команды выполняются последовательно, на экране
  видны и ввод, и вывод; выполнение останавливается на первой ошибке.

Этап 3 — VFS:

- виртуальная файловая система загружается из XML-файла (`--vfs`);
- все данные хранятся только в памяти, на диск ничего не
  распаковывается и не записывается;
- двоичные данные кодируются в base64;
- вложенные каталоги описываются вложенными XML-элементами.

## Команды

| Команда | Описание |
|---------|----------|
| `ls [args...]` | Заглушка: выводит своё имя и аргументы |
| `cd [args...]` | Заглушка: выводит своё имя и аргументы |
| `exit` | Завершает работу эмулятора |
| `vfs-info` | Служебная команда: источник VFS, число каталогов и файлов |

Ошибки:

- `<cmd>: command not found` — неизвестная команда;
- `exit: too many arguments`, `vfs-info: too many arguments` —
  неверные аргументы.

Логика `ls` и `cd` на работе с VFS (этап 4) пока не реализована —
это заглушки.

## Формат VFS (XML)

```xml
<?xml version="1.0" encoding="UTF-8"?>
<vfs>
  <dir name="home">
    <dir name="user">
      <file name="notes.txt">Текстовый файл</file>
      <file name="data.bin" encoding="base64">AAECAw==</file>
    </dir>
  </dir>
  <dir name="tmp"/>
</vfs>
```

- корневой элемент `<vfs>` — это корень `/`;
- `<dir name="...">` — каталог, может содержать `<dir>` и `<file>`;
- `<file name="...">` — файл; содержимое — текст
  (`encoding="text"`, по умолчанию, хранится как UTF-8) или base64
  (`encoding="base64"`, пробелы и переводы строк игнорируются);
- имя не может быть пустым, `.`, `..` и содержать `/`;
- имена в одном каталоге уникальны.

Если VFS не удалось загрузить (файл не найден, неверный XML,
неверный base64 и т. п.), эмулятор печатает `error: ...` и
завершается с кодом 2.

## Коды завершения

| Код | Значение |
|-----|----------|
| 0 | Нормальное завершение |
| 1 | Ошибка стартового скрипта |
| 2 | Ошибка загрузки VFS |

## Параметры командной строки

| Параметр | Описание |
|----------|----------|
| `--vfs PATH` | Путь к XML-файлу VFS |
| `--prompt TEXT` | Пользовательское приглашение к вводу в REPL |
| `--script PATH` | Путь к стартовому скрипту |

При запуске все параметры печатаются в виде строк `[debug] ...`.
Не заданный параметр отображается как `(not set)`.

## Стартовый скрипт

Текстовый файл, одна команда на строку. Пустые строки и строки,
начинающиеся с `#`, пропускаются. Каждая команда выводится после
приглашения, затем её результат — как в диалоге с пользователем.
При первой ошибке скрипт останавливается, эмулятор завершается
с кодом 1. Если скрипт не завершился командой `exit`, эмулятор
продолжает работу в интерактивном режиме.

Примеры: `examples/scripts/*.emu`.

## Требования

Python 3.8+. Внешние зависимости не требуются.

## Сборка и тесты

Сборка не нужна. Запуск тестов:

```
make test
```

или без make:

```
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

## Запуск

```
make run
```

или

```
PYTHONPATH=src python3 -m shell_emulator
```

## Скрипты реальной ОС

Каталог `scripts/` содержит shell-скрипты, вызывающие эмулятор:

| Скрипт | Что проверяет |
|--------|---------------|
| `scripts/stage2_params.sh` | Все параметры командной строки |
| `scripts/stage3_vfs.sh` | Минимальная VFS, несколько файлов, 3+ уровня вложенности, ошибки загрузки, полный стартовый скрипт |

Запуск: `sh scripts/stage2_params.sh`, `sh scripts/stage3_vfs.sh`.

Стартовые скрипты эмулятора для проверки всех команд этапов 1–3:
`examples/scripts/stage3_full.emu` (успешный прогон) и
`examples/scripts/stage3_error_end.emu` (ошибка в конце — остановка).

## Пример использования

```
make run ARGS='--prompt "demo>" --script examples/scripts/basic.emu'
```

Интерактивный сеанс:

```
user@host:~$ ls -l /tmp
ls -l /tmp
user@host:~$ cd docs
cd docs
user@host:~$ foo
foo: command not found
user@host:~$ exit 1
exit: too many arguments
user@host:~$ exit
```

Работа с VFS:

```
make run ARGS='--vfs examples/vfs/deep.xml --prompt "vfs>"'
```

```
vfs> vfs-info
VFS: examples/vfs/deep.xml
Directories: 6
Files: 4
vfs> exit
```

Полный стартовый скрипт с VFS:

```
make run ARGS='--vfs examples/vfs/deep.xml --script examples/scripts/stage3_full.emu'
```

```

examples/scripts/     стартовые скрипты эмулятора
scripts/              скрипты реальной ОС (демонстрация)
Makefile              запуск и тесты
```
