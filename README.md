# Shell Emulator

Эмулятор языка оболочки ОС с консольным интерфейсом (CLI).
Практическая работа по дисциплине «Конфигурационное управление»,
вариант №3.

## Общее описание

Программа имитирует работу в командной строке UNIX-подобной ОС.
Приглашение к вводу формируется на основе реальных данных ОС,
например `username@hostname:~$`. Файловая система — виртуальная (VFS),
загружается из XML-файла и целиком хранится в памяти.

Реализованные этапы:

1. **REPL** — CLI, приглашение из данных ОС, парсер по пробелам,
   сообщения об ошибках, команда `exit`.
2. **Конфигурация** — параметры `--vfs`, `--prompt`, `--script`,
   отладочный вывод параметров, стартовый скрипт.
3. **VFS** — загрузка VFS из XML (текст и base64, вложенные каталоги),
   всё в памяти.
4. **Основные команды** — `ls`, `cd` по VFS, `tree`, `uname`.
5. **Дополнительные команды** — `rm`, `rmdir`, `vfs-load`; изменения
   VFS происходят только в памяти.

## Команды

Пути могут быть абсолютными (`/home/user`) и относительными
(`docs`, `../etc`); поддерживаются `.` и `..`. Выше корня подняться
нельзя. Имена сортируются по алфавиту без учёта регистра.

| Команда | Описание |
|---------|----------|
| `ls [-a] [-l] [путь...]` | Содержимое каталога (по умолчанию — текущего) или сам файл |
| `cd [путь]` | Смена текущего каталога; без аргумента — переход в `/` |
| `tree [-a] [путь]` | Дерево каталога и итог `N directories, M files` |
| `uname [-a] [-s] [-n] [-r] [-v] [-m]` | Данные реальной ОС; без опций — как `-s` |
| `rm [-r] [-f] путь...` | Удаляет файлы; с `-r` — и каталоги рекурсивно |
| `rmdir путь...` | Удаляет пустые каталоги |
| `vfs-load путь` | Загружает новую VFS с диска вместо текущей |
| `exit` | Завершает работу эмулятора |
| `vfs-info` | Служебная: источник VFS, число каталогов и файлов |

### ls

- без опций скрытые файлы (имена на `.`) не показываются, `-a` их
  показывает (записи `.` и `..` не выводятся);
- `-l` добавляет тип (`d` — каталог, `-` — файл) и размер в байтах;
- флаги можно объединять: `-la`, `-a -l`; `--` — конец опций;
- имена выводятся по одному в строке;
- для файла выводится его имя как в аргументе;
- для нескольких путей перед каждым каталогом печатается `путь:`.

### cd

Без аргумента переходит в корень `/` (домашнего каталога в VFS нет).
При ошибке текущий каталог не меняется.

### tree

Печатает дерево в стиле `tree`: корень подписан так, как задан в
аргументе (по умолчанию `.`). Скрытые файлы показываются с `-a`.
Итоговая строка считает каталоги и файлы без корня.

### uname

Значения берутся у реальной ОС: `-s` имя системы, `-n` имя узла,
`-r` релиз, `-v` версия, `-m` архитектура, `-a` все поля. Поля
всегда выводятся в порядке `s n r v m`.

### rm

- без опций удаляет только файлы; каталог — ошибка `Is a directory`;
- `-r` (или `-R`) удаляет каталог со всем содержимым;
- `-f` игнорирует несуществующие пути и отсутствие операндов;
- операнды обрабатываются по порядку, при первой ошибке команда
  прекращает работу (уже удалённое остаётся удалённым);
- нельзя удалить корень (`rm -r /` отклоняется), а также текущий
  каталог и его предков (`Device or resource busy`).

### rmdir

Удаляет только пустые каталоги. Корень, текущий каталог и его предки
удалить нельзя.

### vfs-load

Загружает VFS из XML-файла (формат ниже) и подключает её вместо
текущей; текущий каталог становится `/`. Путь — физический, он
отсчитывается от каталога, откуда запущен эмулятор. Если файл не
удалось загрузить, прежняя VFS остаётся без изменений. Парсер делит
ввод по пробелам, поэтому пути с пробелами не поддерживаются.
Повторная загрузка того же файла возвращает исходное состояние VFS.

### Изменения только в памяти

`rm`, `rmdir` и `vfs-load` меняют только дерево в памяти. XML-файл
на диске никогда не изменяется и не перезаписывается.

### Ошибки

| Сообщение | Причина |
|-----------|---------|
| `<cmd>: command not found` | Неизвестная команда |
| `<cmd>: invalid option -- 'x'` | Недопустимая опция |
| `ls: cannot access 'p': No such file or directory` | Путь не найден |
| `cd: p: No such file or directory` / `Not a directory` | Путь не найден / это файл |
| `cd: too many arguments`, `tree: too many arguments` | Лишние аргументы |
| `tree: p: Not a directory` | `tree` для файла |
| `uname: extra operand 'x'` | Лишний операнд `uname` |
| `rm: missing operand`, `rmdir: missing operand` | Не указан путь |
| `rm: cannot remove 'p': No such file or directory` | Путь не найден |
| `rm: cannot remove 'p': Is a directory` | Каталог без `-r` |
| `rm: it is dangerous to operate recursively on '/'` | `rm -r /` |
| `...: Device or resource busy` | Удаляется текущий каталог или его предок |
| `rmdir: failed to remove 'p': Directory not empty` | Каталог не пуст |
| `rmdir: failed to remove 'p': Not a directory` | `rmdir` для файла |
| `vfs-load: missing path`, `vfs-load: too many arguments` | Неверные аргументы |
| `vfs-load: cannot read VFS ...`, `vfs-load: invalid XML ...` | Файл не найден или некорректен |
| `exit: too many arguments`, `vfs-info: too many arguments` | Аргументы у команд без аргументов |

Если VFS не загружена, эмулятор работает с пустым корнем.

## Параметры командной строки

| Параметр | Описание |
|----------|----------|
| `--vfs PATH` | Путь к XML-файлу VFS |
| `--prompt TEXT` | Пользовательское приглашение к вводу в REPL |
| `--script PATH` | Путь к стартовому скрипту |

При запуске все параметры печатаются в виде строк `[debug] ...`.
Не заданный параметр отображается как `(not set)`.

## Стартовый скрипт

Текстовый файл, одна команда на строку. Пустые строки и строки,
начинающиеся с `#`, пропускаются. Каждая команда выводится после
приглашения, затем её результат — как в диалоге с пользователем.
При первой ошибке скрипт останавливается, эмулятор завершается
с кодом 1. Если скрипт не завершился командой `exit`, эмулятор
продолжает работу в интерактивном режиме.

## Формат VFS (XML)

```xml
<?xml version="1.0" encoding="UTF-8"?>
<vfs>
  <dir name="home">
    <dir name="user">
      <file name="notes.txt">Текстовый файл</file>
      <file name="data.bin" encoding="base64">AAECAw==</file>
    </dir>
  </dir>
  <dir name="tmp"/>
</vfs>
```

- корневой элемент `<vfs>` — это корень `/`;
- `<dir name="...">` — каталог, может содержать `<dir>` и `<file>`;
- `<file name="...">` — файл; содержимое — текст
  (`encoding="text"`, по умолчанию, хранится как UTF-8) или base64
  (`encoding="base64"`, пробелы и переводы строк игнорируются);
- имя не может быть пустым, `.`, `..` и содержать `/`;
- имена в одном каталоге уникальны.

Если VFS не удалось загрузить (файл не найден, неверный XML,
неверный base64 и т. п.), эмулятор печатает `error: ...` и
завершается с кодом 2.

## Коды завершения

| Код | Значение |
|-----|----------|
| 0 | Нормальное завершение |
| 1 | Ошибка стартового скрипта |
| 2 | Ошибка загрузки VFS |

## Требования

Python 3.8+. Внешние зависимости не требуются.

## Сборка и тесты

Сборка не нужна. Запуск тестов:

```
make test
```

или без make:

```
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

## Запуск

```
make run
make run ARGS='--vfs examples/vfs/deep.xml --prompt "vfs>"'
```

или

```
PYTHONPATH=src python3 -m shell_emulator --vfs examples/vfs/deep.xml
```

## Скрипты реальной ОС

Каталог `scripts/` содержит shell-скрипты, вызывающие эмулятор:

| Скрипт | Что проверяет |
|--------|---------------|
| `scripts/stage2_params.sh` | Все параметры командной строки |
| `scripts/stage3_vfs.sh` | Минимальная VFS, несколько файлов, 3+ уровня вложенности, ошибки загрузки |
| `scripts/stage4_commands.sh` | Все режимы `ls`, `cd`, `tree`, `uname` и все их ошибки |
| `scripts/stage5_commands.sh` | Все режимы `rm`, `rmdir`, `vfs-load`, их ошибки и проверка, что XML на диске не меняется |

Запуск: `sh scripts/stage5_commands.sh` (и так же остальные).

Стартовые скрипты эмулятора (`examples/scripts/`):

| Скрипт | Назначение |
|--------|------------|
| `basic.emu`, `stop_on_error.emu` | Этап 2: успешный сценарий и остановка на ошибке |
| `stage3_full.emu`, `stage3_error_end.emu` | Этап 3: команды с VFS, ошибка в конце |
| `stage4_commands.emu` | Этап 4: все режимы команд (с `deep.xml`) |
| `stage4_error_end.emu` | Этап 4: ошибка в конце останавливает скрипт |
| `stage5_commands.emu` | Этап 5: все режимы `rm`, `rmdir`, `vfs-load` (из корня репозитория, с `deep.xml`) |
| `stage5_error_end.emu` | Этап 5: ошибка в конце останавливает скрипт |

## Примеры использования

```
$ make run ARGS='--vfs examples/vfs/deep.xml --prompt "vfs>"'
vfs> ls
etc
home
tmp
vfs> ls -la /home/user
-       16 .profile
d        0 docs
vfs> cd /home/user/docs
vfs> ls
archive
report.txt
vfs> cd ../nope
cd: ../nope: No such file or directory
vfs> cd /
vfs> tree /home/user/docs
/home/user/docs
├── archive
│   └── old.bin
└── report.txt

1 directory, 2 files
vfs> uname -sm
Linux x86_64
vfs> rm /etc/hostname
vfs> rmdir /etc
vfs> rmdir /home
rmdir: failed to remove '/home': Directory not empty
vfs> rm -r /home
vfs> ls
tmp
vfs> vfs-load examples/vfs/multi_files.xml
VFS loaded: examples/vfs/multi_files.xml (0 directories, 4 files)
vfs> foo
foo: command not found
vfs> exit
```

## Структура репозитория

```
src/shell_emulator/   исходный код
  cli.py, config.py   запуск и параметры
  repl.py, script.py  интерактивный режим и стартовый скрипт
  shell.py, parser.py разбор и выполнение строки
  session.py          состояние сеанса (VFS, текущий каталог)
  commands.py         реестр команд, exit, vfs-info, vfs-load
  cmd_nav.py          ls, cd
  cmd_tree.py         tree
  cmd_sys.py          uname
  cmd_edit.py         rm, rmdir
  cmd_util.py         разбор опций, поиск путей
  vfs.py, vfs_xml.py  модель VFS и загрузка из XML
tests/                тесты (unittest)
examples/vfs/         примеры VFS в формате XML
examples/scripts/     стартовые скрипты эмулятора
scripts/              скрипты реальной ОС (демонстрация)
Makefile              запуск и тесты
```
